# 3. 트러블슈팅

형식: 문제 → 원인 → 해결 → 배운 점

아래 원인·해결·배운 점은 당시 일기가 없어, 기억과 코드 변경을 바탕으로 나중에 채운 것이다.

---

## 1. 속도가 느렸음

| | |
|--|--|
| **문제** | 응답이 느렸다. |
| **원인** | 매 요청마다 OpenAI API를 호출하고, 확장 → Render 서버 → OpenAI 왕복이 겹쳤다. 로딩 중이라는 표시도 처음에 약해서 더 길게 느껴졌다. |
| **해결** | 타임아웃(15초)·로딩 점 애니메이션을 넣었다. 모델을 `gpt-4o-mini`로 두고, 입력·출력 길이도 서버에서 잘라 두었다. 체감은 나아졌지만 네트워크 구간은 그대로라 완전하진 않다. |
| **배운 점** | “느리다”는 체감과 실제 병목은 다를 수 있다. UI 피드백만으로도 체감이 많이 바뀐다. |

---

## 2. 원하는 형태로 나오지 않음

| | |
|--|--|
| **문제** | 결과 형식이 기대와 달랐다. 줄 띄어쓰기가 과다하거나, 공식적이어야 하는데 가볍게 나오거나 그 반대인 경우가 있었다. |
| **원인** | 프롬프트에 톤·단락 지시가 약했다. 모델이 마음대로 줄바꿈을 넣거나, 선택한 톤과 다른 말투로 나오기도 했다. |
| **해결** | 시스템 프롬프트에 톤 반영·단락 지시를 넣고, `ensureParagraphs` / `clampOutputLength`로 출력을 다듬었다. 팝업에서 톤을 고르게 한 뒤에도 가끔 어긋나서, 마지막에 프롬프트 문장을 한 번 더 고쳤다 (`069afe3`). |
| **배운 점** | LLM 출력은 한 번에 안 맞춰진다. 프롬프트와 후처리를 같이 손보는 편이 낫다. |

---

## 3. 요약 UI가 불편했음

| | |
|--|--|
| **문제** | 요약을 보여주는 UI가 불편했다. |
| **원인** | 처음 카드는 위치·글자 크기·다크모드 대응이 부족했다. 실패했을 때 다시 누르기도 애매했다. 본문은 `textContent`라 불릿이 평문처럼 보였다. |
| **해결** | 드래그, 글자 크기 ±, 다크모드, Retry, 복사를 붙였다. 가독성은 나아졌지만 마크다운 렌더는 여전히 없다. |
| **배운 점** | 요약 품질과 요약 UI는 따로 봐야 한다. 결과가 괜찮아도 카드가 불편하면 쓰기 싫다. |
