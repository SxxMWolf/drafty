# 5. 최종 정리

아래 소감·우선순위 서술은 당시 정리 메모가 없어, 기억과 코드를 보고 나중에 채운 것이다.

## 한 줄로

브라우저에서 글 고치고 요약하는 Chrome 확장 + Render 백엔드 + iOS 키보드(Enhance만)까지 만든 상태다. 쓰기는 한다. 완성도는 아직 거칠다.

## 결과물

코드 기준, 동작하는 것:

| 항목 | 내용 |
|------|------|
| Enhance | 편집 가능 영역에서 선택 구간을 서버 결과로 치환 |
| Extract | 드래그 가능한 카드에 요약 표시, 복사 / 글자 크기 / 실패 시 Retry |
| 톤 | 팝업에서 5종 저장 (`chrome.storage.sync`) |
| 테마 | 시스템 다크모드에 Extract 카드·팝업 대응 |
| 백엔드 | `/api/enhance`, `/api/extract` → OpenAI `gpt-4o-mini` |
| iOS 키보드 | 선택(또는 앞 문맥) Enhance, 톤 메뉴, 최대 500자 |
| 프로덕션 서버 | `https://drafty-ssa4.onrender.com` |

직접 쓰면서 느낀 것:

- 메일·커뮤니티 초안을 Enhance로 다듬는 흐름은 의도대로 된다.
- Extract는 “긴 글 빠르게 훑기”에는 쓸 만하다. 카드 UX·줄바꿈은 아직 거슬릴 때가 있다.
- iOS는 밖에서 짧게 고칠 때 유용하다. 요약은 처음부터 빼 둔 선택이다.

## 잘된 점 / 아쉬운 점

**잘된 점**

- 탭을 안 나기고 선택 → 버튼 → 결과까지 이어진다.
- 톤을 팝업에 빼 둔 건 나중에라도 만지기 쉽다.
- 서버에 입력·출력 길이 제한, API 키, rate limit을 넣은 건 최소 방어로는 맞다.

**아쉬운 점**

- 속도는 체감상 여전히 길다. (트러블슈팅 1번)
- 톤·단락이 기대와 어긋날 때가 있다. 프롬프트·후처리로 줄였지만 없애진 못했다. (트러블슈팅 2번)
- 요약 카드는 기능을 얹을수록 나아졌지만, “편하다” 수준은 아니다. (트러블슈팅 3번)
- README·버전·주석이 코드와 안 맞는 곳이 남아 있다. 마감 때 문서 정리를 미룬 탓이다.

## 한계 / 임시방편 ↔ 개선 방향

| 한계 / 임시방편 | 내용 | 개선 방향 | 우선순위 |
|-----------------|------|-----------|----------|
| API 키 하드코딩 | 클라이언트(`content.js`)·iOS에 프로덕션 토큰이 하드코딩되어 있음 (값은 코드 참조) | 배포/설정 쪽으로 분리 | 높음 |
| CORS `origin: true` | `cdcaa2b`(2026-02-27)에서 제한 CORS → 전 출처 허용. 의도적 최종값인지 임시방편인지 기록 없음 | 허용 origin을 다시 좁힐지 결정 | 높음 |
| 모델명 불일치 | README Tech Stack은 “GPT-4o / GPT-3.5-turbo”, 코드는 `gpt-4o-mini` | README를 코드 기준으로 수정 | 중 |
| 환경변수 | README `.env` 예시는 `OPENAI_API_KEY`만, 서버는 `API_KEY`도 필수. `dotenv` 패키지 없음 | README에 `API_KEY`·env 주입 절차 반영 | 중 |
| 버전 불일치 | `manifest.json` `1.0.2` vs `popup.html` `Drafty v1.0.1` | popup 표시 버전을 manifest와 맞춤 | 중 |
| Extract 표시 | 본문을 `textContent`로 넣어 HTML/마크다운 렌더 없음. 불릿(`•`)은 평문 | 카드에 줄바꿈·불릿 가독성 개선 | 중 |
| 남은 MVP 주석 | `content.js`: `Default rewrite options for MVP (no UI yet)` — 팝업 UI 추가 뒤에도 남아 있음 | 주석을 현재 상태에 맞게 수정하거나 삭제 | 낮음 |
| iOS Extract | 미지원 (초기 README부터 비지원으로 명시) | 의도적 비지원 유지. 바꿀 계획 없으면 문서에만 명시 | 낮음 (의도적) |
| `background.js` | 주석 2줄만 있고 실행 로직 없음 | MV3 요구만 충족 중이면 유지 가능 | 낮음 |
| 레거시 필드 | iOS에 `polishedText` fallback 남아 있음 | 서버가 `result`만 주면 제거 후보 | 낮음 |

다음에 손댄다면 순서:

1. 키·CORS 정리 (공개 저장소 기준 위험)
2. Extract 카드 가독성 + enhance 톤 안정화
3. README·버전·주석 맞추기

## 회고

처음엔 “선택하면 AI가 고쳐 주는 버튼”만 있으면 된다고 생각했다. 만들다 보니 이름(Polish→Enhance), 서버(Python/Node, Gemini 시험), 출력 형식, UI까지 계속 바뀌었다. 커밋 메시지가 전부 `.`라서 나중에 보면 흐름이 잘 안 보인다. 다음엔 커밋 메시지와 짧은 주간 메모라도 남기는 편이 낫다.

속도·형식·요약 UI 세 가지는 끝까지 따라다녔다. 기능 목록을 채우는 것보다, 쓰는 순간의 불편을 줄이는 데 시간을 더 썼어야 했다.
